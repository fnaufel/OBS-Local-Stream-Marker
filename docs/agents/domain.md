# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before exploring a domain concept, read the root glossary if it exists and any ADRs relevant to the work. If either is absent, proceed. The domain-modeling skill creates these files when terms or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses, and tests. If a needed term is missing, check whether the project already uses another term or record the gap for domain modeling.

Flag proposals that conflict with an ADR and explain why the decision should be revisited.
